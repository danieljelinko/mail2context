# Learnings

| Date | Title | Non-obvious truth | Implication |
|---|---|---|---|
| 2026-09-16 | `protonmail-bridge` launches a GUI | The `/usr/bin/protonmail-bridge` wrapper starts the Qt GUI — even `--help` and `--version` do, then block. The headless core is `/usr/lib/protonmail/bridge/bridge`, which supports `--cli`, `--noninteractive`, `--grpc`. | Always invoke the `/usr/lib` path from scripts or an agent. Wrap any exploratory call in `timeout`. |
| 2026-09-16 | Bridge opens 1143/1025 before any account exists | Bridge binds IMAP 127.0.0.1:1143 and SMTP 127.0.0.1:1025 as soon as it starts — *before* login. | A listening port is **not** evidence of a working mailbox. Health-check by logging in over IMAP, not by `ss`. |
| 2026-09-16 | Bridge needs a paid Proton plan | Bridge is not available on Proton free tier. | If IMAP login fails after a successful Bridge login, check the plan before debugging the client. |
| 2026-09-16 | Bridge vault key vs. gnome-keyring | First run logged `no vault key found, generating new — credentials not found in native keychain` and wrote `~/.config/protonmail/bridge-v3/vault.enc` + `keychain.json`. | Benign once. If it recurs on **every** restart, Bridge isn't persisting to the keyring and the account must be re-added each time — check `keychain_state.json`. |
| 2026-09-16 | Bridge self-update needs a restart to take effect | Bridge announced "a new version (3.26.0) was installed", but the running IMAP server still greets as `Proton Mail Bridge 03.24.02`. The download is staged, not live. | Read the running version from the IMAP greeting, not from the install message and not from `dpkg -l`. Restart Bridge to actually land an update. |
| 2026-09-16 | solvemail's MIME extractors are not MIME extractors | `txt_part`/`html_part`/`att_parts`/`walk_parts` parse **Gmail REST payload dicts** (`{'mimeType':..,'body':{'data':..}}`), not `email.message.EmailMessage`. Only `mk_email`/`_add_att`/`parse_raw` are stdlib-pure. | Over IMAP these cannot be reused verbatim. Use `msg.get_body(('plain','html'))` / `msg.iter_attachments()` instead — ~10 lines. |
| 2026-09-16 | Proton Bridge IMAP offers no THREAD or SORT | Bridge advertises only `AUTH=PLAIN ID IDLE IMAP4rev1 MOVE STARTTLS UIDPLUS UNSELECT`. Server-side threading and sorting are absent. | Thread reconstruction from `Message-ID`/`In-Reply-To`/`References` is mandatory for Proton, not a preference (confirms D-001's risk). Upside: `UIDPLUS` returns the new UID on draft `APPEND`, and `IDLE` gives push instead of polling. |
| 2026-09-16 | Bridge IMAP needs certificate verification disabled | Bridge serves STARTTLS on 1143 with a self-signed cert. A default `ssl` context rejects it; connecting requires `check_hostname=False` + `CERT_NONE`. | Not a misconfiguration to debug. Safe here only because the endpoint is `127.0.0.1` — never copy this setting to a remote IMAP host. |
| 2026-09-16 | The venv was moved, so its console scripts were dead | `.venv/` was copied from the repo's former path; every `bin/` shebang still read `/home/helinko/Work/guess-class/mail2context/.venv/bin/python3`. `uv run python -c ...` worked (uv picks the interpreter) while `uv run pytest` failed with "Failed to spawn". | A moved venv is not relocatable. `rm -rf .venv && uv sync --all-groups` is the fix. Suspect this whenever a module import works but its CLI entry point does not. |
