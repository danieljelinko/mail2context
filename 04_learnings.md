# Learnings

| Date | Title | Non-obvious truth | Implication |
|---|---|---|---|
| 2026-09-16 | `protonmail-bridge` launches a GUI | The `/usr/bin/protonmail-bridge` wrapper starts the Qt GUI — even `--help` and `--version` do, then block. The headless core is `/usr/lib/protonmail/bridge/bridge`, which supports `--cli`, `--noninteractive`, `--grpc`. | Always invoke the `/usr/lib` path from scripts or an agent. Wrap any exploratory call in `timeout`. |
| 2026-09-16 | Bridge opens 1143/1025 before any account exists | Bridge binds IMAP 127.0.0.1:1143 and SMTP 127.0.0.1:1025 as soon as it starts — *before* login. | A listening port is **not** evidence of a working mailbox. Health-check by logging in over IMAP, not by `ss`. |
| 2026-09-16 | Bridge needs a paid Proton plan | Bridge is not available on Proton free tier. | If IMAP login fails after a successful Bridge login, check the plan before debugging the client. |
| 2026-09-16 | Bridge vault key vs. gnome-keyring | First run logged `no vault key found, generating new — credentials not found in native keychain` and wrote `~/.config/protonmail/bridge-v3/vault.enc` + `keychain.json`. | Benign once. If it recurs on **every** restart, Bridge isn't persisting to the keyring and the account must be re-added each time — check `keychain_state.json`. |
| 2026-09-16 | Bridge self-update needs a restart to take effect | Bridge announced "a new version (3.26.0) was installed", but the running IMAP server still greets as `Proton Mail Bridge 03.24.02`. The download is staged, not live. | Read the running version from the IMAP greeting, not from the install message and not from `dpkg -l`. Restart Bridge to actually land an update. |
| 2026-09-16 | solvemail's MIME extractors are not MIME extractors | `txt_part`/`html_part`/`att_parts`/`walk_parts` parse **Gmail REST payload dicts** (`{'mimeType':..,'body':{'data':..}}`), not `email.message.EmailMessage`. Only `mk_email`/`_add_att`/`parse_raw` are stdlib-pure. | Over IMAP these cannot be reused verbatim. Use `msg.get_body(('plain','html'))` / `msg.iter_attachments()` instead — ~10 lines. |
| 2026-09-16 | Proton Bridge IMAP offers no THREAD or SORT | Bridge advertises only `AUTH=PLAIN ID IDLE IMAP4rev1 MOVE STARTTLS UIDPLUS UNSELECT`. Server-side threading and sorting are absent. | Thread reconstruction from `Message-ID`/`In-Reply-To`/`References` is mandatory for Proton, not a preference (confirms D-001's risk). Upside: `UIDPLUS` returns the new UID on draft `APPEND`, and `IDLE` gives push instead of polling. |
| 2026-09-16 | Bridge IMAP needs certificate verification disabled | Bridge serves STARTTLS on 1143 with a self-signed cert. A default `ssl` context rejects it; connecting requires `check_hostname=False` + `CERT_NONE`. | Not a misconfiguration to debug. Safe here only because the endpoint is `127.0.0.1` — never copy this setting to a remote IMAP host. |
| 2026-09-16 | The venv was moved, so its console scripts were dead | `.venv/` was copied from the repo's former path; every `bin/` shebang still read `/home/helinko/Work/guess-class/mail2context/.venv/bin/python3`. `uv run python -c ...` worked (uv picks the interpreter) while `uv run pytest` failed with "Failed to spawn". | A moved venv is not relocatable. `rm -rf .venv && uv sync --all-groups` is the fix. Suspect this whenever a module import works but its CLI entry point does not. |
| 2026-09-16 | `imaplib` does not quote mailbox names | `M.select('All Mail')` fails with `BAD [Error offset=17]: expected CR` — the space ends the command. It must be passed as `'"All Mail"'`. | Quote every mailbox name reaching `imaplib`. Proton exposes `All Mail` and every label as `Labels/<name>`, so spaces are the norm here, not the exception. |
| 2026-09-16 | Proton sends UTC, correspondents send local | The mailbox mixes `+0000` (Proton's own) and `+0200` (French correspondents). Truncating a `Date` header for display hides the offset and makes correctly-sorted threads look scrambled. | Always compare normalised UTC, never the header string. When a thread looks mis-ordered, print the offset before believing it. |
| 2026-09-16 | Most Proton mail has no plain-text part | 85 of 120 sampled messages are HTML-only; only 35 carry `text/plain`. | HTML→text is the **primary** extraction path, not a fallback. A renderer that treats `text/plain` as normal will return nothing for 70% of the mailbox. |
| 2026-09-16 | CSS selectors alone cannot strip quotes | Proton/Gmail wrap quoted originals in `.protonmail_quote`/`.gmail_quote`, but Zimbra and Outlook emit a bare `De:`/`Envoyé:` header block with no class to select. Those are the business correspondents (agroparistech, live.fr, lacsf67.org). | Selector stripping must be paired with a text-level cut at the attribution line. Together: 16/400 messages retained quotes → 1/400, and 30% → 41% of characters removed. |
| 2026-09-16 | Bridge exposes no conversation id | Proton headers include `X-Pm-Internal-Id`, `X-Pm-External-Id`, `X-Pm-Gluon-Id` — all per-message. Nothing identifies a conversation. | There is **no server-side ground truth** to validate thread reconstruction against. Correctness has to come from invariants (`just check`) and manual comparison, not from diffing against Proton. |
| 2026-09-16 | Sorting RFC 2822 Date strings sorts by weekday | `Date` starts with the weekday name, so a string sort orders Fri < Mon < Sat < Thu < Tue < Wed. The thread list looked plausible while being wrong. | Always sort on `thread.sent_at(m)`, never the raw header. Regression test: `test_sent_at_orders_dates_that_string_comparison_would_scramble`. |
| 2026-09-16 | Rewrite images before anchors, never after | Newsletters wrap banners as `<a href><img alt="…"></a>`. Replacing the anchor first destroys the nested `img`, losing its alt — 105 alts in a 200-message sample. | Order matters in `_html_to_text`: `_inline_images` then `_inline_links`. An anchor's `get_text()` is empty for a linked image, so the alt must already be text by then. |
| 2026-09-16 | Grouping only search hits rebuilds partial threads | `--from barbara` returned the FIPDES thread as 6 messages keyed `5f2f67c1`; `just threads` shows the same thread as 14 messages keyed `e95f7a81`. Reconstruction depends on which messages you fetched, so a filtered fetch yields a different thread *and* a different key. | Search must union its hits with the recent window before grouping. Any code path that groups a filtered subset will silently produce partial threads and keys that do not agree with the rest of the tool. |
| 2026-09-16 | Proton reports `\\Recent` on everything and duplicates forwarded flags | A 20-message INBOX fetch returned `\\Recent` on all 20, plus both `$Forwarded` and `Forwarded`. | Do not treat `\\Recent` as "new". Read unread as the *absence* of `\\Seen`, and only when flags were actually fetched — `is_unread` returns False when no flags are present, so a flagless fetch cannot masquerade as all-unread. |
| 2026-09-16 | `just --list` signatures are not copy-pasteable | just arguments are **positional**; the `name="value"` in a listed signature is a default. Pasting `just draft key body account="proton"` passes the literal string `account=proton` as the next positional. | The CLI now detects `name=value` literals and explains. Never document a just recipe by quoting its signature — show a real invocation. |
| 2026-09-16 | Replying to a thread's last sender silently drops the rest | A four-person Zimbra thread's last message was from Élodie, so the reply addressed only her — Barbara, Lucile and Isabelle vanished with no indication. Autoresponders also stack `Auto:` onto the subject, surviving a plain `Re:` strip. | `build_reply` strips `Re:/Fwd:/Auto:` noise, and the CLI prints an `OMITTED` line naming everyone left out. Verify that line before any draft; `--all` copies them in. |
